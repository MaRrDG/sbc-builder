# FC Solver

Finds the cheapest squad from the user's own EA FC 27 club that completes an SBC and shows it on a web-app-lookalike pitch. Read-only toward EA: never buy, sell or submit anything (EA bans for it). Product intent: `PRODUCT.md`, visual rules: `DESIGN.md`.

## Layout
- `server/` Fastify 5 API (Node 24, TS via `tsx`). `ea.ts` EA client + DTO types, `sync.ts` caching/sync + extension-driven cache edits, `sbc.ts` requirement parsing, `solver.ts` problem builder + `diagnose()`, `squad.ts` ported game formulas (rating, chemistry, `isRequirementMet`), `store.ts` JSON cache, `db/` Postgres via Drizzle (`schema.ts`, `sbcs.ts` SBC history + shared brick layouts, migrations in `db/migrations/`, `users.ts` users / persona owners / link tokens, `dailyProfile.ts` username + leaderboard opt-in, `events.ts` admin history log: `solve`/`sync`/`ea_error`/`ea_day`, 180-day prune, `referrals.ts` codes + points transactions), `admin/` admin panel API (`query.ts` pure filters/paging/day keys, `users.ts`, `accounts.ts`, `overview.ts`, `routes.ts`, `auth.ts` admin-only gate, `codes.ts`, `daily.ts` Daily day + leaderboard), `bricks.ts` pure brick rules, `auth.ts` Clerk session → user + persona, `auth-rules.ts` pure link rules, `plan.ts` pure plan/quota rules, `plans.ts` plan + quota for a user, `referrals.ts` pure invite/points rules. `ip-hash.ts` salted IP hash (`IP_HASH_SALT`, /24 or /64) for abuse signals, `csp-report.ts` compact `[csp]` log + `CSP_ENFORCE`, `prune.ts` + `prune-rules.ts` daily drop of unowned EA account caches after 90 quiet days. `gallery/` FUT Gallery planner (`ledger.ts` items ever seen per persona from cache writes, `score.ts` set score + tags, `optimize.ts` best lineup, `compute.ts` per-persona result, `sets.json` catalogue from fut.gg via `scripts/gallery-catalogue.ts`). `objectives/` Objectives squads (Premium; EA objectives relayed into cache key `objectives`): `parse.ts` objective text → conditions, `open.ts` active groups + done flag, `play.ts` CP-SAT play problem + covers re-check + reasons (`noSlot`/`noMatch`/`noXi`/`combo`…), `solve.ts` soft solve (most objectives covered, then rating + chem). `daily/` FC Solver Daily game (`players.ts` players table merge from cache writes, `pool.ts` answer pools (men top 5 / women top 5 / icons, shares `DAILY_WOMEN_SHARE` / `DAILY_ICON_SHARE`), `icons.ts` + `icons.json` every base Icon from fut.gg (nation / position / gender; seeded by `npm run daily:import`, synced rows win), `compare.ts` tiles (incl. gender), `streak.ts` points 7/14/30, `tokens.ts` signed / encrypted game tokens, `service.ts`, `routes.ts`, `username.ts` pure username rules, `leaderboard.ts` pure ranking, `summary.ts` pure admin day summary, `reminder-rules.ts` pure + `reminder.ts` ticker for the Premium streak reminder email at 17:00). `billing/` Paddle subscriptions (`rules.ts` pure: webhook signature, subscription reducer, active rule, log kinds, checkout refusals; `paddle.ts` env config + the only Paddle API calls; `routes.ts` `/api/billing/*` config / checkout / portal / webhook + admin resync; DB in `db/billing.ts`, see `docs/billing.md`). `deletion.ts` account deletion (request / cancel endpoints, Paddle renewal stop, hourly purge ticker; pure rules in `deletion-rules.ts`, DB in `db/deletion.ts`, email in `deletion-mail.ts`). `export.ts` data export readers for `GET /api/me/export` (pure assembler + secret filter in `export-rules.ts`). `squads/` My Squads (Premium; saved squads from the relayed `/squad/list` + `/squad/{id}`, cache keys `squads` + `squads/<id>`): `parse.ts` defensive parsers (raw list kept), `value.ts` pure `squadValue` (club `marketAverage` first, then the squad's itemData, loans 0), `compute.ts` pure rows / squad view (rating + chem via `squad.ts`), `io.ts` cache reads / writes. `history/` own SBC / objective completion history (`extract.ts` cache payload → items, `diff.ts` pure counts vs `completion_marks`, `ingest.ts` onCacheWrite listener; DB in `db/history.ts`).
- `solver/cpsat.py` OR-Tools CP-SAT model, JSON in on stdin, JSON out on stdout.
- `web/src/pwa/` installable app: `platform.ts` pure rules, `install.ts` install prompt + `useInstall()`, `register.ts`; `web/public/sw.js` caches only `/assets/*` + `offline.html` (never `/api/*`, pages or other origins); `components/InstallApp.tsx`. Phones explain that the EA sync runs on the PC.
- `web/src/billing/` Paddle.js loader + `UpgradePage` (`components/billing/`, `/dashboard/upgrade`, its own page without the sidebar).
- `web/src/` React 19 + Vite 8, plain CSS with OKLCH tokens (`styles.css`), Phosphor icons. `App.tsx` holds most state and the views (SBC list/set screen, Club, Evolutions, Gallery, Invite, Settings); `Root.tsx` auth gate (Clerk loaded / signed out / signed in), `components/SignIn.tsx` sign-in screen, `components/admin/` admin panel (tabs, sortable/paged `DataTable`, hand-written SVG `BarChart`, Daily tab), `link.ts` site ↔ extension messages, `components/AccountData.tsx` Settings "Your data" (export download, delete account, `DeletionBanner`; also on the setup screen for users without an EA account), `api.ts` typed fetch helpers; `repeat.ts` repeatability rules, `route.ts` URL routing (screen state lives in the URL; use `navigate`, not local state, for screens); `components/gallery/` Gallery list + set screens (Premium), `components/squads/` My Squads list + squad pitch with AVG under each card (Premium, `/dashboard/squads[/<id>]`), `components/objectives/` Objectives wizard (Premium; pick → formation → squad, step in the URL), `daily/` public `/daily` game (lazy chunk; `ProfilePrompt`, `Leaderboard` dialog), `components/DailyProfileCard.tsx` Settings card, `components/LinkedAccounts.tsx` + `DiscordCard.tsx` Linked accounts screen (`/dashboard/accounts`: Clerk sign-in, Discord, EA accounts; sidebar "Join our Discord" link from `invite`), `legal/` terms / privacy / cookies (`docs.ts` holds both languages as whole documents; operator, contact and date at the top); `landing/` public landing page on `/` (lazy, CSS 3D + scroll-driven animation, demo art in `web/public/landing/`; `#objectives` section lights the `DEMO_SQUAD` cards that cover each demo row); the app lives under `/dashboard`. Global solver settings and per-set local overrides are in `localStorage`; a set with local settings ignores the global ones.
- `discord/` Discord bot, own process (compose service `bot`): `layout.ts` server as data, `sync-plan.ts` pure idempotent planner, `setup.ts` applies it, `index.ts` runtime (language buttons → Pending role, rules ✅ → Member + language, join welcome, pickers, Daily, slash commands), `roles.ts` pure role rules, `i18n.ts` EN / RO strings, `handlers.ts` /sbc + /stats (public answers, ephemeral errors), `poll.ts` pure /poll rules + result embed, `polls.ts` /poll + "poll ended" posts, `embeds.ts`, `api.ts` (only path to data: `/api/bot/*`, server side `server/discord/`).
- `shared/` code the site and the server both import (the runtime image has no `web/`): `confirm-word.ts` pure delete confirm word (any site language, Romanian with or without diacritics); `changelog.ts` changelog entries (en/ro/it) + `APP_VERSION` + pure checks; served on `/changelog` (`web/src/changelog/`, sidebar dot in `seen.ts`) and to the bot (`/api/bot/changelog` → `discord/changelog.ts` posts in `📝・changelog`, English). `paths.ts` `isKnownPath`: unknown paths get the 404 walkout (`web/src/notfound/`, route `notFound`) and HTTP 404 from the server; a new top-level page or app screen must be added there.
- `web/src/ext-version.ts` pure extension minimum-version check (server `minExtension` in `/api/hello`).
- `extension/` Chrome MV3 bridge (session SID, SBC submits, packs, item moves).
- `data/` runtime cache per EA account (`data/accounts/<personaId>/`), git-ignored, contains sessions and keys: never commit or print keys/SIDs.

## Commands
```bash
npm run dev        # API :5178 (watch) + Vite :5173; keep it running, don't kill it after testing
npm run typecheck  # tsc over server + web
npm run build      # web -> dist/
SOLVER_DUMP=/tmp/p.json npm run dev:api && solver/.venv/bin/python solver/cpsat.py < /tmp/p.json
npm test           # node:test unit tests (server/**/*.test.ts, web/src/**/*.test.ts)
npm run db:generate  # new migration after editing server/db/schema.ts
npm run db:import    # backfill Postgres from data/accounts
npm run db:trust     # list / add / --remove trusted accounts
npm run daily:import  # fill the Daily players table from data/accounts + pool sizes
npm run discord:setup  # build / update the Discord server (idempotent)
npm run discord:bot  # run the bot locally
npm run history:baseline  # start the completion history from data/accounts (re-runnable)
```
`DATABASE_URL`, `CLERK_SECRET_KEY` and `VITE_CLERK_PUBLISHABLE_KEY` (Clerk development instance locally) in `.env` (git-ignored, see `.env.example`); local DB `fcsolver` in the `postgresql` container.
Unit tests only for pure logic (`npm test`). Verify with typecheck + build, and against real cached EA data in `data/` or in the browser.

## Rules that matter
- Be gentle with EA: only syncs may call EA (never a page load, set open or solve); everything is cached with `fetchedAt`; sync only when stale (club and SBCs once a day after the 20:01 Europe/Bucharest drop, or on the first web app visit after it; the SBC list also on a visit — SBC page opened or back in the web app — at most every 30 min). The extension relays what the web app loads (`server/events.ts`), which fills the cache for free. Every call is metered per account (`server/meter.ts`, daily cap `EA_DAILY_LIMIT`, 15 min pause on throttling codes).
- Be exact: game formulas are 1:1 ports of the web app code. `found` comes from the `squad.ts` re-check, not from the solver. Don't "simplify" these formulas.
- SBC repeatability comes from the set's `repeatabilityMode`: `NON_REPEATABLE`, `UNLIMITED`, or `REFRESH` (`repeats` per `repeatRefreshInterval` seconds, progress in `timesCompletedInInterval`). `repeatable: true` alone does not mean "can do it now".
- Auth: the site signs in with Clerk (own UI on `@clerk/react` v6 hooks, no Clerk components) and sends `Authorization: Bearer` + `X-Persona`; `server/auth.ts` checks the persona belongs to the user (`personas` table). The extension keeps a per-persona key (`X-Account-Key`) that never reaches the browser; extension 0.8+ links the persona to the signed-in user via `site.js` + a link token in `/api/hello`; taking over another user's persona needs a fresh SID proof; one persona links to at most 3 FC Solver accounts ever (`persona_links`, `overLinkLimit`), the 4th gets a "contact support" notice (`SUPPORT_EMAIL`). Client mode (extension 0.7+): every EA request runs in the web app tab (`extension/hook.js` recipes, `server/jobs.ts` queue); the server keeps no SID and only calls EA once to prove an account. Extensions before 0.7 (server-side SID sync) are refused: `/api/session` answers 410 `extTooOld`. Never add a job recipe that writes to EA.
- Premium has four sources (`server/plan.ts` `planSource`, in this order): admin, Paddle subscription (`subscriptions` rows), paid (`plan` / `premium_until`), Discord boost (`boost_since` / `boost_ended_at`, 12 h grace). Never extend `premium_until` for a boost or a subscription.
- Billing (Paddle, Merchant of Record): subscription state changes ONLY from signed webhooks (`/api/billing/webhook`) or the admin resync, never from the browser or the checkout callback. No card data or API key in the browser; billing is off unless all six `PADDLE_*` env vars are set. The checkout container class must never start with `paddle` (Paddle.js removes those). `docs/billing.md`.
- Site text is translated (English / Romanian / Italian): every string goes through `t()` from `web/src/i18n.tsx`, keys in `web/src/locales/en.ts` + `ro.ts` + `it.ts` (Romanian plurals need `_one`/`_few`/`_other`, Italian `_one`/`_other`); run `npm run i18n:check`. What comes from EA (SBC / challenge names and descriptions, requirement texts, players, clubs, leagues, nations, rarities) stays as EA sends it. Server errors shown to users carry a `msgCode` (+ params) the site translates (`err.*`).
- Responsive: under 860px the sidebar becomes the hamburger menu and the top bar keeps only logo, status and the menu button; check phone width (390px) for any UI change.
- UI must look like the EA web app: dark teal, EA card art, `--go` green only for the primary action / met / selected, `--pos` yellow only for position pills. Controls 8px radius, containers 14px. Respect `prefers-reduced-motion`, WCAG AA, requirement state never by color alone.
- Discord bot: never calls EA or the DB; `/api/bot/*` only, `runSolve` shared with `/api/solve` (same quota).
- Security: headers + a report-only CSP in `server/index.ts` (`csp()`); a new external script / API / font / frame origin must be added there (watch the `[csp]` log). Anything printed from the request host (zip, robots, sitemap, canonical) goes through `publicOrigin()` (`server/origins.ts`). Per-IP limits in `server/limits.ts`.
- Version: everything is v1 (`APP_VERSION`, `package.json` 1.0.0) until the owner says the app launches. A user-visible change → a new entry (or new items in today's entry) in `shared/changelog.ts`, written for users in en / ro / it (each language written, not machine-translated); internal changes get none.
- Analytics: custom events only through `track()` (`web/src/track.ts`, typed list); a new event → `TrackEvents` + `docs/analytics.md`. Never personal data in event props (no email, names, ids, usernames, codes). Cookieless script only.
- New endpoint or payload change → update `docs/api.md`. Extension change → bump `extension/manifest.json` version + `extension/release.json`.
- The extension zip folder stays `fc27-sbc-builder` (users unzip updates over it; a new name = a new extension and lost keys). Domain, container, nginx vhost and `localStorage` keys keep the old `sbc-*` names too; only user-facing branding is "FC Solver".
